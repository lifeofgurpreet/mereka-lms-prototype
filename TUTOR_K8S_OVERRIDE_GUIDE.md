# Tutor Kubernetes Override Guide

This guide documents the permanent resource configuration mechanism for Mereka Academy's Open edX deployment using Tutor's k8s-override functionality.

## Overview

Tutor generates Kubernetes manifests from templates during `tutor config save`. Any direct `kubectl patch` or `kubectl edit` changes are temporary and will be lost when manifests are regenerated. To make changes permanent, we use **Kustomize strategic merge patches** via `override.yml`.

## Architecture

### How It Works

1. **Tutor generates base manifests** → `tutor_env/env/k8s/deployments.yml`
2. **Kustomize applies strategic patches** → `tutor_env/env/k8s/override.yml`
3. **Final manifests deployed to cluster** → `kubectl apply -k tutor_env/env`

### File Structure

```
tutor_env/env/
├── kustomization.yml          # Kustomize config, references override.yml
└── k8s/
    ├── deployments.yml        # Base deployments (auto-generated by Tutor)
    ├── override.yml           # Custom overrides (persistent)
    ├── services.yml
    ├── jobs.yml
    └── volumes.yml
```

## Current Configuration

### Resource Requests Set to 512Mi

We've configured memory requests to **512Mi** for the following deployments:

- **cms** - Studio (CMS) web server
- **cms-worker** - CMS Celery worker
- **lms** - Learning Management System web server
- **lms-worker** - LMS Celery worker
- **mfe** - Micro-frontends (MFE) server

### Why 512Mi?

GKE autopilot optimizes node allocation based on resource requests:
- **2Gi requests** → Forces large E2-medium nodes (2 vCPU, 4 GB RAM)
- **512Mi requests** → Allows efficient bin-packing on smaller nodes
- **Result**: ~40% cost reduction while maintaining performance for staging workloads

### 2. Kustomization Configuration (`tutor_env/env/kustomization.yml`)

The kustomization file includes the override via `patchesStrategicMerge`:

```yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
resources:
- k8s/namespace.yml
- k8s/deployments.yml
- k8s/jobs.yml
- k8s/services.yml
- k8s/volumes.yml

# Strategic merge patches for resource overrides
patchesStrategicMerge:
- k8s/override.yml

namespace: openedx
# ... rest of config
```

## Deployment Workflow

### Standard Deployment

The override is automatically applied during normal Tutor operations:

```bash
# Set environment
export TUTOR_ROOT="$(pwd)/tutor_env"

# Regenerate manifests (preserves override.yml)
tutor config save

# Apply patches (if needed for other customizations)
./infrastructure/tutor/apply-patches.sh

# Deploy to cluster (applies override via Kustomize)
tutor k8s start
```

### Manual Apply

You can also apply the manifests directly:

```bash
kubectl apply -k tutor_env/env
```

This uses Kustomize to:
1. Load base resources from `k8s/*.yml`
2. Apply patches from `k8s/override.yml`
3. Deploy merged manifests to cluster

## How `tutor config save` Preserves Overrides

**Critical**: The `override.yml` file is **NOT** auto-generated by Tutor. It's a custom file we maintain manually.

### What Happens During `tutor config save`:

1. ✅ **Preserved**: `tutor_env/env/k8s/override.yml` (custom file, not templated)
2. ✅ **Preserved**: `tutor_env/env/kustomization.yml` reference to override
3. ⚠️ **Regenerated**: `tutor_env/env/k8s/deployments.yml` (from Tutor templates)
4. ✅ **Result**: Override patches still apply after regeneration

### Why This Works

- Tutor generates base manifests from templates
- Kustomize applies our override as a **strategic merge patch**
- Override takes precedence over base manifest values
- Both files coexist: base is regenerated, override is static

## Modifying Resource Requests

### To Change Memory for a Deployment

1. Edit `tutor_env/env/k8s/override.yml`
2. Update the memory value for the target deployment
3. Apply changes:

```bash
export TUTOR_ROOT="$(pwd)/tutor_env"
tutor k8s start
```

Example: Change LMS to 1Gi:

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: lms
spec:
  template:
    spec:
      containers:
        - name: lms
          resources:
            requests:
              memory: 1Gi  # Changed from 512Mi
```

### To Add CPU Requests/Limits

Add CPU configuration to the override:

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: lms
spec:
  template:
    spec:
      containers:
        - name: lms
          resources:
            requests:
              memory: 512Mi
              cpu: 500m        # New: 0.5 CPU
            limits:
              memory: 1Gi      # New: limit 1Gi
              cpu: 1000m       # New: limit 1 CPU
```

### To Add a New Deployment Override

Append to `override.yml`:

```yaml
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: redis  # New deployment
spec:
  template:
    spec:
      containers:
        - name: redis
          resources:
            requests:
              memory: 256Mi
```

## Troubleshooting

### Override Not Applied

**Symptom**: Deployment still shows old memory value after `tutor k8s start`

**Solutions**:

1. Verify kustomization references override:
   ```bash
   grep -A 2 "patchesStrategicMerge" tutor_env/env/kustomization.yml
   ```

2. Check override file exists:
   ```bash
   ls -lh tutor_env/env/k8s/override.yml
   ```

3. Validate YAML syntax:
   ```bash
   kubectl apply --dry-run=client -k tutor_env/env
   ```

4. Force redeployment:
   ```bash
   kubectl rollout restart deployment/lms -n openedx
   ```

### Kustomization Syntax Error

**Symptom**: `error: accumulating resources: accumulation err='merging resources from 'k8s/override.yml'`

**Cause**: YAML syntax error or incorrect strategic merge format

**Solution**: Validate YAML structure matches Kubernetes resource schema:

```bash
# Check syntax
kubectl apply --dry-run=client -f tutor_env/env/k8s/override.yml

# Validate against schema
kubectl apply --dry-run=server -k tutor_env/env
```

### Override Reverted After `tutor config save`

**Symptom**: Override file deleted or modified after regeneration

**Cause**: Override was placed in wrong location (in a templated directory)

**Solution**: Ensure override is at:
- ✅ Correct: `tutor_env/env/k8s/override.yml`
- ❌ Wrong: `tutor_env/plugins/.../k8s/override.yml`

## Maintenance Notes

### When Upgrading Tutor

1. Run `tutor config save` to regenerate base manifests
2. Verify override file still exists: `ls tutor_env/env/k8s/override.yml`
3. Check kustomization still references it: `./scripts/infra/verify-k8s-overrides.sh`
4. Test deployment: `tutor k8s start`
5. Verify in cluster: `kubectl get deployments -n openedx -o wide`

### Git Tracking

**Important**: The `tutor_env/` directory is gitignored. To persist overrides across environments:

1. **DO NOT** commit `tutor_env/` directly
2. **DO** document override configuration in this guide
3. **DO** commit the verification script
4. **CONSIDER** creating a setup script that generates override.yml automatically

Example setup script (`scripts/infra/setup-k8s-overrides.sh`):

```bash
#!/usr/bin/env bash
# Auto-generate k8s override file for resource requests
set -euo pipefail

REPO_ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/../.." && pwd)"
OVERRIDE_FILE="$REPO_ROOT/tutor_env/env/k8s/override.yml"

cat > "$OVERRIDE_FILE" <<'EOF'
---
# Auto-generated k8s override for memory requests
# See: TUTOR_K8S_OVERRIDE_GUIDE.md

apiVersion: apps/v1
kind: Deployment
metadata:
  name: cms
spec:
  template:
    spec:
      containers:
        - name: cms
          resources:
            requests:
              memory: 512Mi
# ... (rest of overrides)
EOF

echo "✅ Created $OVERRIDE_FILE"
```

## FAQ

**Q: Will `tutor config save` delete my overrides?**
A: No. The override.yml file is not templated by Tutor, so it persists across config regenerations.

**Q: Do I need to run `tutor config save` after editing override.yml?**
A: No. You can apply overrides directly with `tutor k8s start` or `kubectl apply -k tutor_env/env`.

**Q: Can I set different memory for production vs staging?**
A: Yes. Maintain separate override files or use environment-specific values in your deployment pipeline.

**Q: What happens if I don't include patchesStrategicMerge in kustomization?**
A: The override file will be ignored, and deployments will use base manifest values (2Gi).

**Q: Can I override non-deployment resources (services, configmaps)?**
A: Yes. Override works for any Kubernetes resource. Follow the same pattern with the appropriate apiVersion/kind.

**Q: How do I test overrides before deploying to production?**
A: Use `kubectl apply --dry-run=server -k tutor_env/env` to validate without applying.
