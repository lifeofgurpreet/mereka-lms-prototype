## 7. Breakpoint-Debt Summary (user's original concern)

The user's concern was "the lesson page was loading MFE but the design was off, there's a lot of breakpoint debt and layout issues."

Observed evidence:

1. **Course-end/exit route at mobile** (D-08, D-09): The `/course-end` path at 390px redirects into a unit URL and renders with 986px horizontal overflow — content is 2.5× the viewport width. This matches the "layout issues" description directly.

2. **Courseware at tablet** (D-03): Hard "error loading this course" at 1024px — entire learning surface blocked.

3. **Progress tab falls back to legacy Django LMS** (D-06): At mobile (and times out at desktop/tablet), the `/progress` route on the MFE sends the user to the legacy LMS view. This is a routing/redirect misconfiguration, not a CSS issue, but produces a visually inconsistent experience (different chrome, cookie banner, old theme).

4. **Course home renders partially** (body 338 chars) but the loading state is visible as a near-blank page — spinner only, no content after networkidle. This suggests an API call is failing silently and the error boundary does not activate.

5. **Header slot structure**: The header renders (visible in screenshots with "Support / testadmin" buttons) but the learning-specific header extension points (`header_learning.v1`, course info slot) do not expose `data-slot-id` attributes, making automated slot verification against this surface impossible without upstream MFE changes.
