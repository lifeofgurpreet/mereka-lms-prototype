## 3. Classification Rules (referenced inline per row)

**KEEP-AS-HINT**: Introducing commit cites a ticket/bead/spec reference (`Refs #109`) AND at
least one runtime reference exists in `_mereka_lms/mfe_runtime/` — the slot is actively wired
into the JS runtime definition surface.

**PROMOTE-CANDIDATE**: Runtime reference exists AND the audit bundle §4b/§4a annotation
explicitly calls out product-value (e.g. "Priority 3" in inventory doc, or inventory note
identifies the slot as a planned product feature). A separate bead must be filed to write
acceptance criteria — one bead per slot.

**DEFAULT**: Slot was registered with no detectable references anywhere, no commit-level intent
signal, and no product annotation in any inventory/audit document. Applied only when all four
grep checks return empty AND there is no inventory doc note. No slot in this investigation set
meets all conditions; none are classified DEFAULT.

**NEEDS-OWNER**: Any ambiguity, missing runtime ref when expected, explicit "high risk /
not recommended" flag in audit bundle requiring human review, or slots that are v1/v2 version
pairs where only one may be active. Default when in doubt.

## 7. What Must NOT Be Done

- **No bulk retirement PR.** Each slot removal requires its own bead, a reviewer decision, and
  a PR that touches only that slot. The OVERSPEC count is a spec-maintenance signal — not a
  cleanup mandate.
- **No mass Hint removal.** Hint registrations in the edX plugin-slot pattern are often
  intentional API-surface stabilizers for planned future work. Zero runtime refs is not
  sufficient evidence of "dead code" — it may indicate planned work that has not yet shipped.
- **No slot deletions in the same PR as spec changes.** Spec extension and code removal are
  orthogonal concerns; never bundle them.
- **No action on any NEEDS-OWNER slot** until the named investigation bead produces a
  written conclusion reviewed by at least one Opus-tier agent.
- **Do not treat `sequence_container.v1`** as trivially removable. The audit bundle explicitly
  flags regression risk. Any action requires product and platform sign-off.
- **Do not treat `video_transcript_additional_translations_component.v1`** as removed by
  virtue of the "Not Recommended" annotation. That annotation is guidance, not a retire order.
