# Documentation Delivery Checklist

Use this before publishing or merging documentation.

## Structure
- [ ] Title and purpose clear in first paragraph
- [ ] Table of contents for docs > 100 lines
- [ ] Code examples tested and working
- [ ] Links to related specs and docs

## Quality
- [ ] No broken internal links
- [ ] Commands include expected output examples
- [ ] Troubleshooting section for operational docs
- [ ] Runbook format for production procedures

## Compliance
- [ ] ADR created for architectural decisions
- [ ] Runbook exists for production-facing features
- [ ] No secrets or credentials in examples
