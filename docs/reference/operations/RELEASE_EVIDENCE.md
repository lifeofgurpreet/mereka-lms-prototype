# Release Evidence Bundle

**Status**: Active
**Last Updated**: 2026-02-24

> Defines what constitutes a release evidence bundle for Mereka LMS, how it is assembled,
> and the retention policy governing long-term storage.

---

## What Is a Release Evidence Bundle?

A release evidence bundle is a point-in-time snapshot of all artefacts that prove a
specific release was built, scanned, tested, and deployed correctly. It enables:

- Post-incident root cause analysis without relying on ephemeral CI logs
- Compliance and audit responses
- Rollback decision support
- Evidence chain for security reviews

---

## Bundle Contents

Every bundle lives under `var/release-evidence/<sha>/` (gitignored) and contains:

| File | Source | Description |
|------|--------|-------------|
| `changelog.txt` | `git log` | Commits from previous tag to this SHA |
| `image-tags.txt` | `deploy/k8s/overlays/production/kustomization.yaml` | Image names and tags at release time |
| `sbom.cdx.json` | `var/` or CI artifact | CycloneDX SBOM produced by `build-tutor-images.yml` |
| `trivy-suppression.txt` | `.trivyignore` | Record of accepted vulnerability suppressions |
| `security-scan.log` | CI artifact (Trivy) | Container image vulnerability scan output |
| `codeql.log` | CI artifact (CodeQL) | Static analysis result summary |
| `trufflehog.log` | CI artifact (TruffleHog) | Secret scanning result summary |
| `argocd-sync.log` | ArgoCD CLI / UI export | Sync status at deployment time |
| `smoke-test.log` | `scripts/qa/` | Post-deploy smoke test results |
| `manifest.json` | Assembled by script | File list with SHA-256 checksums and metadata |

### Required vs Optional

| File | Required? | Notes |
|------|-----------|-------|
| `changelog.txt` | Yes | Always generated from git |
| `image-tags.txt` | Yes | Always generated from kustomization |
| `manifest.json` | Yes | Always generated by assembly script |
| `sbom.cdx.json` | If available | Produced only when CI builds images |
| `trivy-suppression.txt` | If `.trivyignore` exists | Copied from repo root |
| `security-scan.log` | If available | Download from CI after scan completes |
| `codeql.log` | If available | Download from CI after analysis completes |
| `trufflehog.log` | If available | Download from CI after scan completes |
| `argocd-sync.log` | Recommended | Capture from ArgoCD UI or CLI |
| `smoke-test.log` | Recommended | Capture from `make qa-smoke` output |

## Retention Policy

### GitHub Actions Artifacts

| Release type | Retention |
|-------------|-----------|
| All CI runs (untagged) | 90 days |
| Tagged releases (`v*`) | 90 days (GitHub limit; GCS provides the 1-year tier) |

The workflow `release-evidence-bundle.yml` uploads with `retention-days: 90`.

### Google Cloud Storage (Tagged Releases)

Tagged releases (`v*`) are additionally stored in GCS for 1 year:

```
gs://mereka-lms-release-evidence/releases/<tag>/
```

To upload after a tag is pushed:

```bash
gsutil -m cp -r var/release-evidence/<sha>/ \
  gs://mereka-lms-release-evidence/releases/<tag>/
```

GCS lifecycle policy enforces deletion after 365 days. Configure via:

```bash
gsutil lifecycle set scripts/infra/assemble-release-evidence.sh \
  gs://mereka-lms-release-evidence
```

### Local `var/` Directory

`var/release-evidence/` is gitignored. Clean up manually when disk space is a concern:

```bash
# Remove bundles older than 90 days
find var/release-evidence/ -maxdepth 1 -type d -mtime +90 -exec rm -rf {} +
```

## Assembling a Bundle

### Automatic (CI — Recommended)

On every push of a `v*` tag, `release-evidence-bundle.yml` runs automatically and:

1. Checks out the tag
2. Runs `scripts/infra/assemble-release-evidence.sh`
3. Uploads the bundle as a GitHub Actions artifact (90-day retention)

### Manual Assembly

```bash
# Assemble from current HEAD
./scripts/infra/assemble-release-evidence.sh

# Assemble from a specific tag
./scripts/infra/assemble-release-evidence.sh v1.2.3

# Assemble from a specific SHA
./scripts/infra/assemble-release-evidence.sh abc1234
```

The script prints the bundle directory path on completion.

### Adding Security Scan Outputs

After a CI run completes, download artefacts and copy into the bundle:

```bash
# Example: download Trivy output from GitHub Actions
gh run download <run-id> --name trivy-report -D /tmp/trivy-report
cp /tmp/trivy-report/trivy.log var/release-evidence/<sha>/security-scan.log
```

### Adding ArgoCD Sync Log

```bash
# Capture ArgoCD sync status
argocd app get mereka-lms --output json > \
  var/release-evidence/<sha>/argocd-sync.log
```

## Retrieving a Past Bundle

### From GitHub Actions UI

1. Navigate to **Actions** → **Release Evidence Bundle** workflow
2. Find the run matching the tag or SHA
3. Click **Artifacts** → download `release-evidence-<tag>`

### From GitHub CLI

```bash
# List available runs for the workflow
gh run list --workflow=release-evidence-bundle.yml --limit 20

# Download a specific run's artifacts
gh run download <run-id> --name release-evidence-<tag> -D /tmp/evidence
```

### From GCS (Tagged Releases, 1-Year Archive)

```bash
# List available tagged bundles
gsutil ls gs://mereka-lms-release-evidence/releases/

# Download a specific tag bundle
gsutil -m cp -r gs://mereka-lms-release-evidence/releases/<tag>/ \
  /tmp/evidence/<tag>/
```

## Verifying Bundle Integrity

The `manifest.json` at the root of every bundle contains SHA-256 checksums for each file.
Verify integrity after download:

```bash
cd var/release-evidence/<sha>/
python3 -c "
import json, hashlib, pathlib, sys
manifest = json.loads(pathlib.Path('manifest.json').read_text())
errors = []
for entry in manifest['files']:
    path = pathlib.Path(entry['path'])
    if not path.exists():
        errors.append(f'MISSING: {path}')
        continue
    digest = hashlib.sha256(path.read_bytes()).hexdigest()
    if digest != entry['sha256']:
        errors.append(f'TAMPERED: {path} (expected {entry[\"sha256\"][:12]}..., got {digest[:12]}...)')
if errors:
    print('INTEGRITY FAILURES:')
    for e in errors: print(' ', e)
    sys.exit(1)
print(f'OK: {len(manifest[\"files\"])} files verified')
"
```
