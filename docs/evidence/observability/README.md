# Observability Evidence Index

Date: 2026-02-25

This directory stores evidence bundles generated by observability runtime checks and
pilot execution runs.

## Canonical bundle naming

- `pilot-nonprod-YYYYMMDD-HHMMSS.md`
  - Non-production tracing pilot proof package (AC-005 / OBS-025).
- `trace-correlation-YYYYMMDD-HHMMSS.md`
  - Correlation proofs for request/trace/log evidence.
- `drift-closeout-YYYYMMDD-HHMMSS.md`
  - Retrospective closeout bundles for parity/observability gap reviews.

## Required contents for any pilot bundle

Each bundle should include:

- `evidence_identity` string (env/profile/context/project) copied from the
  first-class evidence index.
- Observability artifacts used to produce the conclusion:
  - `observability-compliance-runtime.json`
  - `observability-runtime-verify-runtime.md`
  - `observability-first-class-runtime-evidence-index.json`
  - `observability-correlation-headers-runtime.txt`
  - `observability-logging-pipeline-runtime.txt`
  - `observability-tracing-runtime.txt`
- One concrete trace-flow proof:
  - Trace ID
  - Request ID
  - Route exercised
  - Tempo query/result link or CLI proof
- One concrete log proof:
  - Matching trace/request ID in structured logs
  - Query used and result snippet hash (or screenshot reference)

## Evidence retention

- Keep one signed bundle per successful pilot lane per day while the pilot is in
  stabilization.
- Archive bundles after six weeks into external runbook storage per team policy.

## Trace-back check

For each new nonprod pilot trace bundle, verify:

1. `observability-tracing-runtime.txt` includes a pass/ready signal for Tempo.
2. `observability-correlation-headers-runtime.txt` captures `X-Request-ID` and
   `traceparent` at ingress/app boundary.
3. `observability-logging-pipeline-runtime.txt` includes AC-LOG checks for source,
   labels, and PII/retention behavior.

No empty directories are permitted in release review handoffs.


## How to generate a nonprod pilot bundle

Use:

```bash
./scripts/qa/build-observability-tracing-pilot-bundle.sh --env nonprod --mode runtime --strict
```

This generates a timestamped bundle under this directory and copies all first-class evidence artifacts used in the review.
